# mpdecimal (Rust)

Rust translation of libmpdec from mpdecimal 4.0.1, produced by c2rust. One
source tree builds for all targets; the configuration is selected by
`target_pointer_width`:

- 64-bit targets: CONFIG_64 (`uint128`)
- 32-bit targets: CONFIG_32 (`ansi32`)

Two crates:

- `mpdecimal-core` (`core/`): the translation. It exports no C symbols by
  itself, so it can be linked together with C libmpdec.
- `mpdecimal-sys` (`sys/`): the C ABI of libmpdec (`mpdecimal.h`) on top of
  mpdecimal-core (`staticlib`, `rlib`). Its functions are wrappers generated
  from the header; the globals that C code assigns (`mpd_mallocfunc`,
  `mpd_traphandler`, ...) are exported by mpdecimal-core with the feature
  `capi`, which mpdecimal-sys enables.

## Layout

- `core/`: mpdecimal-core, written by `c2rust/install.py`. Do not edit by
  hand. Regenerate with `c2rust/transpile-all.sh`.
- `sys/`: mpdecimal-sys. `sys/src/capi.rs` is generated by `systest/gen.py`;
  `sys/src/manual.rs` holds the wrappers written by hand, for functions whose
  mpdecimal-core counterpart no longer has the C signature.
- `c2rust/`: the translation pipeline, its run log (`c2rust/RUNS.md`) and the
  test scripts. See [c2rust/README.md](c2rust/README.md).
- `libmpdec/`, `configure.ac`: the C sources and header configuration of
  mpdecimal 4.0.1, which are the input of the translation.
- `tests/`: the short tests of mpdecimal 4.0.1, unmodified.
- `systest/`: compile-time checks of the C ABI against `mpdecimal.h`, and
  the generator of `sys/src/capi.rs`.
- `testit-2.5.1/`: mpdecimal-testit 2.5.1, the long tests. The feature
  `test-hooks` is needed only for these tests.

## Tests

The upstream C tests are linked with the staticlib of mpdecimal-sys:

```sh
CRATE=root c2rust/test-short.sh macos-aarch64-uint128   # one target
CRATE=root c2rust/test-all.sh                           # all targets
```

The translation is frozen on the short tests (`tests/runshort.sh`,
`tests/runshort_alloc.sh`). They passed on macOS aarch64/x86_64, Linux
aarch64/x86_64/i686/s390x/armv7, wasm32-wasip1 and Windows x86_64, with and
without `test-hooks`, before the split into `core/` and `sys/`; since the
split, they were run on macOS aarch64 only.

`systest/` checks the C ABI against `mpdecimal.h` at compile time: the
signatures of all functions (of mpdecimal-sys) and globals, struct layouts and
field types, typedefs and constant values (of mpdecimal-core), for CONFIG_64
and CONFIG_32. The checks are generated by `systest/gen.py` (bindgen) and
committed:

```sh
cargo check -p systest
cargo check -p systest --features test-hooks
cargo check -p systest --target i686-unknown-linux-gnu
cargo check -p systest --target i686-unknown-linux-gnu --features test-hooks
```
